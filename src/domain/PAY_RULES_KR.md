# Корейские правила оплаты труда — спецификация расчёта

Справочник для `payroll.js`. Актуально на 2026-08. Все ссылки — на 근로기준법 (Закон о трудовых стандартах, далее ЗТС), если не указано иное.

---

## 0. ФУНДАМЕНТ

Вся логика стоит на одном утверждении:

> **Оплата = сумма по минутам смены. Каждая минута классифицируется независимо по трём осям, множители осей СКЛАДЫВАЮТСЯ (не перемножаются) и применяются к 통상시급 (ordinary hourly wage).**

```
pay = Σ_minutes( ordinaryHourly / 60 × multiplier(minute) )

multiplier(m) = 0                                    если m — перерыв
              = 1.0 + night(m) + timeAxis(m)         иначе
```

Три оси, полностью независимые друг от друга:

| Ось | Условие | Значение |
|---|---|---|
| `night(m)` | минута попадает в 22:00–06:00 | `0.5` иначе `0` |
| `timeAxis(m)` — вариант «обычный день» | не превышен ни дневной порог, ни недельные 40 ч | `0` |
| | превышен любой из порогов (переработка) | `0.5` |
| `timeAxis(m)` — вариант «휴일» | накопленных в этой смене ≤ 8 ч | `0.5` |
| | накопленных > 8 ч | `1.0` |

Порог переработки — **дизъюнкция двух счётчиков**: дневного (обычно 8 ч, накапливается внутри смены) и недельного (40 ч, накапливается с начала недели). Час — переработка, если превышен хотя бы один. Двойного начисления не возникает: ось всё равно даёт максимум `0.5`.

Из этого выводится вся таблица ставок — её не нужно хранить, она вычисляется:

| Ситуация | 1.0 + night + timeAxis | Итог |
|---|---|---|
| обычная дневная | 1.0 + 0 + 0 | **1.0×** |
| только ночь | 1.0 + 0.5 + 0 | **1.5×** |
| только переработка | 1.0 + 0 + 0.5 | **1.5×** |
| переработка + ночь | 1.0 + 0.5 + 0.5 | **2.0×** |
| 휴일 ≤ 8 ч | 1.0 + 0 + 0.5 | **1.5×** |
| 휴일 ≤ 8 ч + ночь | 1.0 + 0.5 + 0.5 | **2.0×** |
| 휴일 > 8 ч | 1.0 + 0 + 1.0 | **2.0×** |
| 휴일 > 8 ч + ночь | 1.0 + 0.5 + 1.0 | **2.5×** |

### Пять инвариантов, которые нельзя нарушать

**И1. Ось «ночь» независима от факта переработки.**
Ночная надбавка начисляется, даже если человек отработал ровно свою норму. ЗТС ст. 56 п. 3 не содержит условия о превышении нормы.

**И2. В 휴일 ось переработки НЕ добавляется отдельно.**
После поправки 2018 г. и решения ВС 2011다112391 работа в 휴일 сверх 8 часов даёт `1.0`, и это уже включает в себя компонент переработки. Максимум с ночью — `2.5×`, не `3.0×`.

**И3. Рабочий день определяется по дате НАЧАЛА смены (принцип 역일).**
Смена 20:00 сб → 06:00 вс — это ОДИН рабочий день, отнесённый к субботе. Часы после полуночи не обнуляют счётчик 8 часов и не получают статус воскресного 휴일.

**И4. Перерыв не оплачивается и не считается ни по одной оси.**
Критично: перерыв, попавший в 22:00–06:00, съедает ночную надбавку за этот час; перерыв вне окна — не съедает. Разница реальная в деньгах. Поэтому нужно **время начала перерыва, а не только длительность**.

**И5. База — 통상시급, а не то, что фактически платят.**
Надбавка никогда не начисляется на надбавку. См. §2.

## 1. Шлюзы применимости (проверять ДО расчёта)

Прежде чем считать множители, нужно определить, применяется ли ст. 56 вообще. Три независимых флага:

```js
// settings.legal
{
  isEmployee: true,        // 근로자성 — признан ли работником по ЗТС
  workplaceSize: 5,        // 상시 근로자 수 — постоянная численность
  article63: false,        // 감시·단속적 승인 или 관리감독자 (ЗТС ст. 63)
}
```

Из них выводятся коэффициенты осей:

```js
const premiumsApply   = legal.isEmployee && legal.workplaceSize >= 5
const nightFactor     = premiumsApply ? 0.5 : 0
const overtimeFactor  = premiumsApply && !legal.article63 ? 0.5 : 0
const holidayFactor   = premiumsApply && !legal.article63 ? 0.5 : 0   // ≤8ч; >8ч → удвоить
```

### Правила шлюзов

| Флаг | Значение | Эффект |
|---|---|---|
| `isEmployee: false` | freelance / soleProprietor / selfEmployed / платформенный курьер | **Все** оси = 0. Только `1.0×`. ЗТС не применяется вообще |
| `workplaceSize < 5` | 5인 미만 사업장 | **Все** оси = 0. ЗТС ст. 56 не применяется (ст. 11 п. 2). Реформа по поэтапному распространению на малые предприятия надбавок пока НЕ дошла — на 2026-08 не применяется |
| `article63: true` | охрана, консьерж, вахтёр с санкцией министерства; управленческий персонал | Оси «переработка» и «휴일» = 0, **ось «ночь» СОХРАНЯЕТСЯ**. Это самая частая ошибка в расчётах |

`EMPLOYMENT_TYPES` из `types.js` маппится на `isEmployee`:
```js
const NON_EMPLOYEE = ['freelance', 'soleProprietor', 'selfEmployed']
// dispatch (파견직) и subcontract (도급) — работники, но у ДРУГОГО работодателя;
// размер предприятия берётся у фактического нанимателя
```

Расчёт `workplaceSize` (상시 근로자 수): сумма человеко-дней за расчётный месяц ÷ число дней работы предприятия. Считаются все формы занятости, кроме самого работодателя.

## 2. 통상시급 — база всего расчёта

```js
ordinaryHourly = ordinaryMonthlyWage / monthlyStandardHours
```

### Числитель — что входит в 통상임금

| Компонент | Входит | Примечание |
|---|---|---|
| Оклад (기본급) | ✅ | |
| Регулярные фиксированные надбавки (должностная, за стаж, квалификацию) | ✅ | это `allowances.custom` |
| Регулярный бонус (정기상여금) | ✅ **с 19.12.2024** | делить на 12 и добавлять к месячной базе |
| Бонус с условием «числиться на дату выплаты» (재직조건부) | ✅ **с 19.12.2024** | ВС 2020다247190, 2023다302838 — признак «фиксированности» (고정성) отменён |
| Премия по результату (성과급) | ❌ | |
| Разовые выплаты | ❌ | |
| Сами надбавки за переработку/ночь/휴일 | ❌ | И5 |

**⚠️ Расхождение с текущим кодом:** сейчас `sumAllowances()` добавляет надбавки к итогу месяца, но `getHourlyRate()` берёт ставку только из `payRates`. Юридически регулярные фиксированные надбавки должны поднимать 통상시급 → и, следовательно, все премии. Сейчас премии занижены у всех, у кого есть фиксированные надбавки.

### Знаменатель — 209

```
209 = (40 ч норма + 8 ч оплачиваемого 주휴) × (365 / 7 / 12)
    = 48 × 4.345
```
Для нестандартных графиков пересчитывать; 209 — дефолт для 40-часовой недели.

## 3. Классификация дня

Это отдельный шаг перед расчётом множителей. **Выходной ≠ 휴일** — юридически разные вещи.

```js
function dayKind(dateStr, settings) → 'holiday' | 'restDay' | 'workday'
```

| Категория | Что это | timeAxis |
|---|---|---|
| **휴일** (holiday) | 주휴일 (обычно вс), 관공서 공휴일 + 대체공휴일, 노동절 1 мая | ветка «휴일»: `0.5` / `1.0` |
| **무급휴무일** (restDay) | обычно **суббота** — не выходной день по закону, а просто неоплачиваемый нерабочий | ветка «обычный день»: работа = **переработка**, `0.5` |
| **근로일** (workday) | обычный рабочий день | ветка «обычный день» |

**⚠️ Расхождение с текущим кодом:** `isWeekend()` трактует субботу и воскресенье одинаково и даёт `rate * 8 * 1.5` за весь день. Юридически:
- воскресенье (주휴일): да, `1.5×` до 8 ч, но `2.0×` после 8 ч — порога сейчас нет;
- суббота: это переработка. Если недельная норма уже выбрана — `1.5×` (совпадает случайно). Если нет — только `1.0×`.

Какой день является 주휴일 — задаётся договором, не обязательно воскресенье. Нужна настройка `weeklyHolidayDay: 0` (0 = вс).

Первомай (노동절, переименован из 근로자의 날 с 2026-05-01) — оплачиваемый выходной для **всех** предприятий, включая <5 человек, но надбавка за работу в этот день — только при `workplaceSize >= 5`.

관공서 공휴일 (гос. праздники) применяются к частному сектору только при `workplaceSize >= 5`.

## 4. Порог переработки

```js
function overtimeThreshold(day, settings) → minutes
```

| Случай | Порог |
|---|---|
| Обычный работник | `8 ч` в день |
| **단시간근로자** (part-time) | **договорные часы этого дня**, а не 8 ч |
| 휴일 | `8 ч` (переключает `0.5 → 1.0`) |

**Part-time (Закон о срочных и part-time работниках, ст. 6):** переработка считается от собственных договорных часов работника, надбавка `+50%` начисляется, даже если недельный итог меньше 40 ч. Лимит — 12 ч/нед сверх договорных, требуется согласие.

### Недельный порог (второго порядка)

Помимо дневных 8 ч, переработкой являются часы сверх **40 в неделю**, даже если каждый день был ≤ 8 ч. Требует прохода по неделе, а не по дню. Двойной учёт исключить: час считается переработкой один раз — по дневному ИЛИ по недельному порогу.

Лимит: 40 + 12 = **52 ч/нед**. Ночная работа из-под лимита не выводит.

**Отрасли-исключения (ЗТС ст. 59)** — наземные/водные/воздушные перевозки, услуги при перевозках, **здравоохранение**: по письменному соглашению можно свыше 12 ч/нед, но обязателен **непрерывный отдых ≥ 11 ч** между сменами. На множители не влияет — только на лимиты и валидацию.

## 5. Канонический алгоритм

```js
function calcShiftPay(shift, settings) {
  const { start, end, breaks, dateStr } = shift   // breaks: [{start, minutes}]
  const legal      = gateOf(settings)             // §1
  const hourly     = ordinaryHourlyOf(settings)   // §2
  const kind       = dayKind(dateStr, settings)   // §3 — по дате НАЧАЛА (И3)
  const threshold  = overtimeThreshold(shift, settings) // §4
  const win        = settings.nightShift ?? { windowStart: '22:00', windowEnd: '06:00' }

  let worked = 0                    // оплачиваемые минуты ЭТОЙ смены
  let week   = weekMinutesBefore(shift, settings)  // оплачиваемые минуты недели ДО смены
  let units  = 0                    // сумма множителей × минуты

  for (const m of minutesOf(start, end)) {        // end может перейти за полночь
    if (isBreak(m, breaks)) continue              // И4 — не оплачивается, не копится

    const night = inWindow(m, win) ? legal.nightFactor : 0

    let timeAxis
    if (kind === 'holiday') {
      // Ветка 휴일: ось переработки не участвует (И2), порог всегда 8 ч
      timeAxis = worked < 480 ? legal.holidayFactor : legal.holidayFactor * 2
    } else {
      // Ветка обычного дня: переработка по дневному ИЛИ недельному порогу
      const isOvertime = worked >= threshold || week >= 2400   // 2400 мин = 40 ч
      timeAxis = isOvertime ? legal.overtimeFactor : 0
      week += 1
    }

    units += 1.0 + night + timeAxis
    worked += 1
  }

  return hourly * units / 60
}
```

Ключевые детали реализации:
- итерация по минутам, `worked` инкрементируется **только** для оплачиваемых минут — перерыв не двигает порог 8 ч;
- `night` берётся от `legal.nightFactor`, а не константы `0.5` — так шлюзы §1 работают автоматически;
- множитель ночи применяется к минуте независимо от того, переработка это или нет (И1);
- в ветке `holiday` ось переработки не участвует (И2).

Текущий `nightHoursOf()` уже сканирует по минутам — структура совместима, но нужно вернуть не «часы ночи», а поток классифицированных минут.

## 6. Тестовые векторы

`ordinaryHourly = 10320` (минималка 2026), `workplaceSize ≥ 5`, `isEmployee`, `!article63`.

| # | Вход | Ожидаемые «ставки» | Сумма | Проверяет |
|---|---|---|---|---|
| 1 | Пн, 22:00–06:00, перерыв 02:00 (60 мин) | 7 × 1.5 = **10.5** | 108 360 | И1 — ночь без переработки |
| 2 | Пн, 09:00–01:00, перерыв 12:00 (60 мин) | 8×1.0 + 4×1.5 + 3×2.0 = **20.0** | 206 400 | наложение ночь+переработка |
| 3 | Вс (휴일), 20:00–06:00, перерыв 02:00 (60 мин) | 2×1.5 + 6×2.0 + 1×2.5 = **17.5** | 180 600 | порог 8 ч в 휴일, И2 |
| 4 | #3, перерыв перенесён на **20:30** | 1×1.5 + 7×2.0 + 1×2.5 = **18.0** | 185 760 | **И4** |
| 5 | #3, но `workplaceSize = 4` | 9 × 1.0 = **9.0** | 92 880 | шлюз 5인 미만 |
| 6 | #3, но `article63 = true` | 2×1.0 + 7×1.5 = **12.5** | 129 000 | ст. 63: ночь есть, 휴일 нет |
| 7 | #3, но `isEmployee = false` | **0** ставок сверх договора | — | ЗТС не применяется |
| 8 | Пн, 19:00–01:00, part-time, договор 5 ч | 3×1.0 + 2×1.5 + 1×2.0 = **8.0** | 82 560 | порог по договору, §4 |
| 9 | Сб (`restDay`), 20:00–06:00, перерыв 02:00, **за неделю уже 40 ч** | 2×1.5 + 7×2.0 = **17.0** | 175 440 | недельный порог |
| 10 | То же, что #9, но **за неделю 32 ч** | 2×1.0 + 6×1.5 + 1×2.0 = **13.0** | 134 160 | `restDay` ≠ `휴일` |

**#3 vs #4** — тот же график и та же длительность перерыва, разное его положение: 60 минут внутри окна 22:00–06:00 против 60 минут вне его. Разница `0.5` ставки = 5 160 ₩ за смену. Проверка И4 и достаточное основание хранить время начала перерыва, а не только длительность.

**#9 vs #10** — одна и та же суббота даёт `17.0` или `13.0` в зависимости от того, выбрана ли недельная норма. Проверка того, что суббота не приравнена к воскресенью (§3): по ветке 휴일 обе дали бы `17.5`.

**#3 vs #6** — при статусе по ст. 63 исчезает надбавка за 휴일, но остаётся ночная. Самая частая ошибка ручных расчётов.

## 7. Производные величины

Эти суммы считаются от результатов §5, каждая — по своим правилам.

| Величина | Надбавки включены? | Формула / примечание |
|---|---|---|
| **Проверка на минималку** (최저임금) | ❌ **исключены** | Сравнивать с 10 320 ₩/ч нужно зарплату **без** надбавок за переработку/ночь/휴일. Нельзя засчитывать ночные в счёт минималки |
| **평균임금** (средний заработок) | ✅ включены | `(вся зарплата за 3 мес) / (календарных дней за 3 мес)` |
| **퇴직금** (выходное пособие) | ✅ через 평균임금 | `평균임금 × 30 дней × (стаж в днях / 365)` |
| **통상임금** | ❌ | И5 |
| **4대보험** | ✅ | входят в базу взносов |

### Необлагаемая часть ночных (소득세법 시행령 §17)

Для 생산직 근로자 (производство, стройка, доставка, уход, общепит, водители):

```js
const TAX_FREE_2026 = {
  annualCap: 2_400_000,          // ₩/год на все надбавки за переработку/ночь/휴일
  monthlyFixedWageMax: 2_600_000, // 월정액급여 (без самих надбавок) — было 2 100 000
  priorYearTotalMax: 37_000_000,  // 총급여 за прошлый налоговый период — было 30 000 000
}
```
Пороги повышены с 2026. Важно: сами надбавки **не входят** в `월정액급여`, поэтому большие ночные не выбивают из льготы.

## 8. Ночная работа: ограничения и запреты (валидация, не расчёт)

### Запреты по категориям (ЗТС ст. 70)

```js
const NIGHT_WORK_RESTRICTION = {
  adultFemale:   'consent',            // 18+ женщины — согласие работницы
  pregnant:      'request+approval',   // явное письменное требование + разрешение министерства
  postpartum1yr: 'consent+approval',   // согласие + разрешение (в течение 1 года после родов)
  minor:         'consent+approval',   // младше 18 лет
}
```
Плюс перед подачей на разрешение — добросовестные консультации с представителем работников (ст. 70 п. 3).
Для беременных дополнительно: **любая** сверхурочная работа запрещена (ст. 74 п. 5).

### Медосмотр за ночную работу (산업안전보건법)

Триггер за 6 месяцев — любое из:
```js
const HEALTH_CHECK_TRIGGER = {
  regularShiftsPerMonth: 4,      // непрерывные 8ч смены, включающие 00:00–05:00
  nightHoursPerMonth: 60,        // часов в окне 22:00–06:00
  irregularShifts6mo: 24,        // накопительно
  irregularHours6mo: 360,        // накопительно
}
```
Периодичность: до назначения → в течение 6 мес после → далее ежегодно. Хороший кандидат для уведомления в приложении.

### Коэффициент 1.3 при признании профзаболевания

При оценке хронической перегрузки (сердечно-сосудистые/цереброваскулярные) ночные часы считаются **с надбавкой 30%**:
```js
adjustedWeeklyHours = dayHours + nightHours * 1.3
```
Пороги: `> 60 ч/нед` за 12 недель (или `> 64` за последние 4) → сильная связь; `> 52 ч/нед` → связь растёт. Исключение: работники по ст. 63 п. 3.

| # | Где | Проблема | Влияние |
|---|---|---|---|
| 1 | `getHourlyRate()` | Фиксированные надбавки и регулярные бонусы не входят в 통상시급 → все премии занижены (§2) | Высокое, у всех с надбавками |
| 2 | `calcDayGross()`, `calcDayExtras()` | Нет порога 8 ч для 휴일 (`0.5 → 1.0`). Вместо него — настраиваемый `weekendOvertime` | Высокое на длинных праздничных сменах |
| 3 | `isWeekend()` | Суббота и воскресенье трактуются одинаково; 무급휴무일 не отличается от 휴일 (§3) | Высокое |
| 4 | `paidNightHoursOf()` | `breakMinutes` — скаляр, вычитается из ночных часов целиком. Если перерыв вне окна 22:00–06:00, ночные занижены (И4, векторы #3/#4). Нужно `breaks: [{start, minutes}]` | Среднее, 0.5 ставки/смена |
| 5 | — | Нет шлюзов `workplaceSize` / `article63` / `isEmployee` (§1) | Критично по корректности для части пользователей |
| 6 | `calcDayGross()` | База жёстко `rate * 8` — фактическая длина дневной смены не учитывается | Среднее |
| 7 | — | Недельный порог 40 ч не отслеживается (§4) | Низкое/среднее |
| 8 | `overtimeThreshold` | Порог всегда 8 ч; для part-time должен быть договорным (§4) | Среднее для `partTime` |

Пункты 1–4 меняют суммы у существующих пользователей — нужен либо флаг миграции, либо пересчёт только новых записей (в коде уже есть принцип «сохранённые дневные gross не пересчитываются задним числом» — его стоит сохранить).
